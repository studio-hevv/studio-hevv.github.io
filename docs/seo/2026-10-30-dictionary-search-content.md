# 검색 유입 콘텐츠 개선 절차: 첫 수동 사례

이번 사례는 기존 `/biblical-dict/` 소개 페이지에 검색 예시와 사용 순서를 보강한다. 운영 게시일과 이후 성과는 별도 비공개 기록에서 관리한다. Search Console 원본·기준값·관찰 기록은 저장소 밖 비공개 위치에 보관한다.

1. 키워드 필터 없이 전체 속성의 확정 검색 실적을 수집한다. 검색어×페이지와 페이지 전체 집계를 구분하고 데이터 누락·지연을 기록한다.
2. 실제 서비스와 검색 의도를 대조해 후보를 고른다. 노출과 클릭만으로 콘텐츠 부족을 단정하지 않는다.
3. 현재 페이지와 제품 구현을 확인한다. 기존 페이지 개선, 별도 글, 보류 중 적합한 방식을 고른다.
4. 변경 가설·변경 전 기준값·범위·예상 효과의 불확실성을 비공개 기록에 남긴다.
5. 작게 수정하고 HTML·메타데이터·링크·화면·제품 사실을 검증하고 독립 검토한다.
6. 승인된 운영 게시일과 커밋을 기록한다. 게시 전후의 완전한28일 구간을 같은 기준으로 비교한다. 표본이 작으면 관찰 기간을 늘리고 동시 변경의 영향도 고려한다.

## 이번 변경

한국어·스트롱 번호 검색, 사랑/H2617/G26 예시, 검색 결과 선택 후 뜻풀이·구절 확인을 소개한다. 검증된 기능을 설명하며 직접 원어 철자 검색이나 음성 재생을 새로 약속하지 않는다. 기존 아이콘·스크린샷·다운로드 주소·스타일은 보존한다.

HTML/JSON-LD/XML, 내부 링크·이미지 응답, 데스크톱과390px모바일 렌더링을 확인했다. 새 기능을 구현하지 않은 편집 변경이라 문구를 복제하는 테스트는 추가하지 않았다. 독립 검토에서 새로 도입한 문제는 발견되지 않았다. 출시 버전의 앱 실행 검증은 하지 않았다.

현재는 수동 절차 기록이며 자동 실행·일정·자동 게시는 구현하지 않았다. 근거가 약한 날에는 글을 억지로 만들지 않는다.

원격 통합 시 이미 추가된 스트롱 번호 안내에 승인된 사용 순서를 합쳤다. 기존 섹션 앵커와 유료 앱 FAQ·설치 경로를 보존했으며, FAQ 본문과 JSON-LD의 답변을 일치시켰다. 원격의 사이트맵 수정일2026-10-30을 유지했다. 통합 후 기존 SEO 테스트11개도 통과했다.
